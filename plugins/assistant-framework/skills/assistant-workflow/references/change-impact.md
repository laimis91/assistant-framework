# Change-impact gates

Use when behavior, cosmetic, or a locality claim affects verification scope. Cosmetic
work records applicability without an impact ledger.

Every behavior change records scope, applicability reason, and causal local
evidence. Local work keeps its selected verification and fresh independent review;
it needs no common artifact. Discovery records the bounded base/candidate universe,
unknown material boundaries, and the same `artifact_identity` only for shared,
materially unresolved, or explicitly carried expanded work.

Expanded work uses assistant-review's
[expanded-work checklist](../../assistant-review/references/change-impact.md#expanded-work-checklist);
no script or runtime is needed. Before any source/test mutation or dispatch,
record a passing checklist result for `pre_build` against the capture, the
independent expected context, and the assessment; `pre_build` validates the task
packet. A status or `checklist_result_ref` alone is insufficient: the result names
each item with its evidence. The expanded path covers relevant call,
configuration, registration, event, state, public, wrapper, added, and removed
consumers and transitions.

`prepare_only` keeps applicability and artifact identity without implementation
completion or post-Build review claims. Requested/required readiness plan review
and selected research isolation remain applicable as preparation evidence.
Otherwise completion refreshes universe/context, records a passing `completion`
checklist result, binds verification identity and assistant-review's original
`scope_manifest`, `coverage_ledger`, review snapshot, and concern bindings, and
preserves original ledgers and terminal coverage/CLEAN/ISSUES_FIXED checks. The
fresh independent reviewer checks the checklist result against the diff. Shared
fanout alone does not require Pack, strict, QA, or a different Build lane; existing
triggers apply. Light expanded work records assistant-review final-summary and
delegation-path refs.

Workflow 17.0 replaced the former checker script's receipt (`validator_result_ref`)
with the checklist result (`checklist_result_ref`); see
[legacy compatibility](legacy-compatibility.md) for older packets.
