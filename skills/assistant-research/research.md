# Source research

Use direct source research for ordinary factual questions, comparisons, and
requests for understanding. Choose the smallest search that can answer the
material question; a tier name is an effort cue, not a source or angle quota.

1. Start with the best primary or authoritative source for the claim. Check
   identity, date, scope, and whether it actually supports the conclusion.
2. Seek independent corroboration, alternatives, and counterevidence when
   uncertainty or the consequences of error warrant it. Repeated copies of one
   source do not add independent evidence. Expand into a domain investigation
   only when it changes the answer.
3. Resolve or expose consequential disagreements. Separate sourced facts from
   inference. Confidence is claim-specific: a narrow official specification can
   be decisive for that specification; a disputed causal claim needs more than
   an authoritative name or a count of citations.
4. Stop when the material question is answered within the available budget, or
   report the exact remaining gap. Do not keep searching solely to fill a tier.

Quick work may need one strong source; broader work may need varied sources and
iterative follow-ups. Never call a mechanism proven merely because several
sources repeat it. Candidate mechanisms retain support, counterevidence, gaps,
and a concrete validation method; executed validation is needed for cause or
improvement claims.

Verify every public URL presented per `url-verify.md`; omit unverified links.
Repository, authenticated, or offline authoritative evidence may use a safe
stable relative locator, opaque record ID, or bibliographic citation. Never
expose credentials, PII, private endpoints, traversal, or absolute host paths.
Conflict sources follow the same rules.

`source_research` stays direct-capable. Five-lens research is only for an explicit
request or a consequential contested decision that actually needs independent
perspectives, root synthesis, and a separate peer critique; see
`five-lens-briefing.md`. A comparison or a "deep" request alone is no trigger.

Return the answer with supporting citations, material conflicts, uncertainty,
and next steps only where needed. Omit empty headings and internal process fields.
For existing v3 structured consumers/audit fixtures, `contracts/index.yaml`
selects the unchanged output and gates; that fixture's numeric budgets and
HIGH/MEDIUM/LOW count rules do not define ordinary confidence assessment.
