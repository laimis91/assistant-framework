# Brief: invoice export (from product, 2026-10-28)

## What we need

Finance users filter invoices in the Invoices screen and then copy rows into
spreadsheets by hand. We want an export.

1. An **Export CSV** button on the Invoices screen exports exactly the invoices
   that match the current filters, including all pages, not only the visible
   page.
2. Every exported row includes a `currency` column with the invoice's ISO 4217
   code (for example `EUR`). Amounts are exported as stored, without conversion.
3. Exports larger than 10,000 rows are not downloaded in the browser. Instead
   the user sees "We'll email you a link", and receives an email with a download
   link that expires after 7 days.

## Dependency

The export must be generated by the reporting service's `/v3/exports` endpoint.
Platform is building it under PLAT-212; it is not deployed yet (target: 2026-11-20).

## Not in this ticket

PDF export is out of scope. It will be handled separately after the CSV export
ships.

## Background (for context)

The current Invoices screen was built on the legacy reporting module, which
renders server-side and paginates at 50 rows. The legacy module has known
issues: it times out on filters spanning more than a year, its column
configuration is stored per browser, and it does not support saved filters.
Engineering has discussed replacing it with the new grid component used by the
Payments screen; that migration is estimated at three sprints and has not been
scheduled. The reporting service v3 also adds streaming responses, which the
Payments team uses for its own exports.
